## 2. Поднятые сервисы — и почему именно они

Перечисли, что реально поднял (проверь через `docker ps`), и обоснуй выбор каждой технологии.

| Сервис | Роль в стеке | Почему именно он (а не альтернатива) |
|---|---|---|
| MinIO | S3-совместимое объектное хранилище (сюда физически падают parquet-файлы) | Бесплатный S3-совместимый сервис, легко разворачивается в Docker (использовала форк pgsty/silo, так как оригинальный MinIO теперь требует лицензию).|
| PostgreSQL | БД, где Lakekeeper хранит метаданные каталога | Надежная реляционная СУБД, нативно поддерживается Lakekeeper для хранения служебных данных.|
| Lakekeeper | Iceberg REST Catalog — каталог метаданных таблиц | Реализует стандартный REST-каталог для Iceberg. Позволяет отделить метаданные от файлов данных и удобно управлять ими.|
| Trino | SQL-движок: ходит в Lakekeeper за метаданными и читает/пишет данные в MinIO | Быстрый распределенный движок для ad-hoc аналитики. Идеально подходит для быстрых запросов к объектному хранилищу через коннектор Iceberg.|
| (BI: Superset / Metabase) | отчёт/дашборд поверх Gold |  Легкий в запуске BI-инструмент с открытым исходным кодом. Имеет встроенный драйвер для Trino, позволяет строить графики без написания кода.|


### Скрипты, которыми поднимал стек

Вставь свои команды (`docker run` / `docker-compose.yml` / shell-скрипт), которыми реально поднял сервисы, с кратким комментарием к каждой.

```bash
# MinIO (объектное хранилище)
docker run -d --name lakehouse-minio -p 9000:9000 -p 9001:9001 -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin -v minio-data:/data pgsty/silo:latest server /data --console-address ":9001"

# PostgreSQL (база для Lakekeeper)
docker run -d --name lakehouse-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -v pg-data:/var/lib/postgresql/data postgres:17

# Trino (SQL-движок)
docker run -d --name trino -p 8080:8080 -v "${PWD}\catalog:/etc/trino/catalog" trinodb/trino:476

# Metabase (BI)
docker run -d --name metabase -p 3000:3000 metabase/metabase:latest
```

## 4. Медальон — решения по каждому слою

Как заполнять:
- **Строк** — `SELECT count(*) FROM таблица`;
- **Вес, МБ** — размер файлов таблицы в MinIO (консоль → бакет → объекты) или `SHOW STATS`;
- **Формат** — `PARQUET` / `ORC`;
- **Сжатие** — `NONE` / `SNAPPY` / `GZIP` / `ZSTD`;
- **Партиционирование** — по какой колонке (или «нет»);
- **Обоснование** — почему выбрал именно такой формат + сжатие + партиционирование для этого слоя и твоего объёма данных.

## 5. Тесты производительности

Прогони свой запрос и замерь, сколько он выполняется. Затем пересоздай Bronze с разным сжатием и сравни, как кодек влияет на время запроса и размер данных.

| Сжатие на Bronze | Время запроса | Размер Bronze, МБ | Твой вывод (что лучше и почему) |
|---|---|---|---|
| GZIP | 32,99| 234,3 | GZIP дает чуть меньший размер на самой большой таблице, но распаковывается медленнее.|
| ZSTD | 30,46| 232,1| ZSTD - лучший выбор: файлы в сумме меньше, и читаются они на 2,5 секунды быстрее благодаря современному алгоритму распаковки|

> Время запроса удобно смотреть в логах Trino (`docker logs trino`) или через `system.runtime.queries`.
